硬體鐵律：異號相加（正+負）與同號相減（正-正、負-負）絕對不可能發生 Signed Overflow！電路也可簡化為 Overflow = CarryIn[31] XOR CarryOut[31]。

MIPS 溢位例外處理 vs. 無號指令Exception Trap
  • 觸發 Overflow Exception：add、addi、sub。發生溢位時硬體將溢位指令位址存入 EPC (Exception Program Counter)，跳轉至 OS 例外處理位址 4000 0040_hex（透過 mfc0 讀回 EPC）。
  • 完全忽略 Overflow：addu、addiu、subu。常用於 C 語言無號整數與記憶體位址指標運算（C 語言規格忽略整數溢位，故 C 編譯器預設產生 addu/subu）。
多媒體飽和運算（Saturating Arithmetic）Media / DSP
  • 為何不用 Modulo Wrap-around？若將音量或像素亮度調高時發生 2's complement 溢位，正極值 +max 會瞬間跳變成負極值 -min（產生刺耳爆音或全黑雜訊點）。
  • Saturating 機制：運算超過上界時直接夾止（Clamp）於最大正值，低於下界時夾止於最小負值。廣泛內建於 SIMD 多媒體指令集。

4-bit 直式乘法追蹤：1000₂ (8) × 1001₂ (9) = 72m + n bits
Multiplicand = 1000₂ (8), Multiplier = 1001₂ (9)
• Bit 0 = 1 → 加入 1000₂ << 0 = 0001000₂
• Bit 1 = 0 → 加入 0000₂ << 1 = 0000000₂

  • mult rs, rt / multu rs, rt：將 64-bit 乘積高 32 bits 存入 HI，低 32 bits 存入 LO；兩條指令皆不觸發硬體 Overflow Exception。
  • mfhi rd / mflo rd：Move From HI / LO 至通用暫存器。
  • 軟體如何檢查 32-bit 乘法溢位？
    • Unsigned (multu)：只要 HI != 0 即溢位。
    • Signed (mult)：若 HI 不是 LO[31] 的全 0 或全 1 符號延伸，即溢位。

Restoring Division 演算法與兩代硬體演進33 → 32 Steps
  • 恢復餘數法（Restoring Division）每步流程：
    1. Remainder = Remainder - Divisor（先試減）
    2. 若 Remainder ≥ 0：商左移補 1；
    3. 若 Remainder < 0：加回 Divisor 恢復原餘數（Remainder += Divisor），商左移補 0。
  • Version 1 (64-bit ALU)：Divisor 放在 64-bit 暫存器左半部，每次右移 1 bit，共需 32+1 = 33 steps。
  • Optimized Divider (32-bit ALU)：Divisor 固定 32-bit，改將 64-bit Remainder 左移，並把 Quotient 併入 Remainder 右半部空出的 32 bits（32 steps 完成！）。

MIPS div / divu 暫存器配置與必考陷阱Exam Trap
  • LO = Quotient (商數)，HI = Remainder (餘數)（切勿記反！記憶法：商是主要結果放 LO）。
  • 為什麼同一顆 64-bit Shift Register 不能同時做乘又做除？
    改良版乘法器需將 64-bit Product 向右移位（Shift Right）；改良版除法器需將 64-bit Remainder 向左移位（Shift Left），故需雙向移位暫存器。
  • MIPS 硬體不檢查除以零與 -2³¹ / -1 溢位：div 與 divu 發生除以 0 時不會觸發硬體 Trap，必須由編譯器插入 bne + break 軟體檢查！

IEEE 754 正規化數值通用公式： Value = (-1)S × (1 + Fraction) × 2(Exponent - Bias)  ｜  Single Bias = 127，Double Bias = 1023
教科書範例：將 -0.75₁₀ 轉為 IEEE 754Worked Example
  • Step 1 (二進位科學記號)：
    -0.7510 = -3/4 = -0.112 = (-1)1 × 1.12 × 2-1
  • Step 2 (讀取 S 與 Fraction)：
    S = 1；隱含小數點前 1 後，Fraction = .1000...00₂
  • Step 3 (加上 Bias)：
    • Single：Exp = -1 + 127 = 126 = 011111102 → 0xBF400000
    • Double：Exp = -1 + 1023 = 1022 = 011111111102

§3.5 · Floating-Point Addition Algorithm & Datapath

浮點數加法 4 大步驟追蹤（0.5 + (-0.4375)）與雙 ALU 硬體架構

wiki/concepts/ieee-754-floating-point-and-hardware.md
4-bit 尾數浮點加法追蹤：0.5₁₀ + (-0.4375₁₀)4-Step Trace
  • 初始轉換：
    0.510 = 1.0002 × 2-1；-0.437510 = -7/16 = -1.1102 × 2-2
  • Step 1 (對齊小數點 Align Binary Point)：
    將指數較小者（2-2）的尾數右移 1 bit 對齊較大指數 2-1：
    -1.1102 × 2-2 → -0.1112 × 2-1
  • Step 2 (尾數相加 Add Significands)：
    1.0002 + (-0.1112) = 0.0012 × 2-1
  • Step 3 (正規化與檢查 Overflow/Underflow)：
    左移 3 bits 並將指數減 3：0.0012 × 2-1 → 1.0002 × 2-4
    （檢查 -126 ≤ -4 ≤ +127，無 Overflow/Underflow）
  • Step 4 (捨入 Round to 4 bits)：
    尾數已恰好 4 bits：1.0002 × 2-4 = 1/16 = 0.062510（若捨入再次進位需回到 Step 3 重新 Normalize）。

§3.5 · Floating-Point Multiplication & Accurate Rounding

浮點數乘法 5 步驟追蹤與 Guard / Round / Sticky 精確捨入（ulp）

wiki/concepts/ieee-754-floating-point-and-hardware.md
浮點數乘法 5 步驟：0.5 × (-0.4375) = -0.218755-Step Trace
  • 輸入：0.5 = 1.0002 × 2-1；-0.4375 = -1.1102 × 2-2
  • Step 1 (指數相加並減去一個 Bias)：
    直接把兩個 Biased Exponents 相加會包含 2 × Bias，必須減掉一個 127：
    Expbiased = (-1 + 127) + (-2 + 127) - 127 = 126 + 125 - 127 = 124 (即真實指數 -3)
  • Step 2 (尾數相乘 Multiply Significands)：
    1.0002 × 1.1102 = 1.1100002
  • Step 3 (正規化與檢查 Overflow/Underflow)：
    1.1100002 × 2-3 已是 1.xxxx 格式，且 -126 ≤ -3 ≤ +127
  • Step 4 (捨入至 4 bits)：保留 4 bits 得 1.1102 × 2-3
  • Step 5 (設定符號位元)：異號相乘 S = 0 ⊕ 1 = 1 ⇒ -1.1102 × 2-3 = -7/32 = -0.2187510
IEEE 754 精確算術：Guard / Round / Sticky 與 ulp0.5 ulp Accuracy
運算中間過程在尾數最右側額外保留 3 個保護位元：
1 . x x x ... x ｜ G (Guard) ｜ R (Round) ｜ S (Sticky)
  • Guard bit (G)：尾數 LSB 右側第 1 個額外位元。
  • Round bit (R)：尾數 LSB 右側第 2 個額外位元。
  • Sticky bit (S)：Round bit 右側所有被移出位元的邏輯 OR（只要有任何一個 1 曾被右移掉，Sticky 就黏在 1，用來區分「剛好在正中間 0.5000...」與「大於中間 0.5001...」）。
  • 4 種 Rounding Modes：朝 +∞、朝 -∞、Truncate (朝 0)、以及預設 Round to Nearest Even（偶數捨入）——當落點恰好在正中間（G=1, R=0, S=0）時，強制將結果最低有效位元捨入為偶數 0，消除大量統計偏誤。
  • Units in the Last Place (ulp)：尾數 LSB 的誤差位數。IEEE 754 保證加減乘除與開根號誤差皆在 0.5 ulp 以內！
課本 Guard/Round 十進位範例：計算 2.56 × 100 + 2.34 × 102（假設僅 3 位有效十進位數）Worked Example

• 有 Guard & Round digits：對齊得 0.0256 × 102 + 2.3400 × 102 = 2.3656 × 102（Guard=5, Round=6）→ 超過一半進位得 2.37 × 102。
• 無 Guard & Round digits：右移對齊時 56 直接被截斷為 0.02 × 102 + 2.34 × 102 = 2.36 × 102（產生 1 ulp 誤差）。

Fallacy 1：算術右移 = 除以 2n？Negative Trap
以 -5 ÷ 4 為例（-5 = 1111...1011₂）：
• C 整數除法 -5 / 4（朝 0 捨入）：
商 = -1，餘數 = -1
• 算術右移 -5 >> 2（朝 -∞ 捨入）：
1111...1110₂ = -2（不等於 -1！）

結論：sra 僅在非負整數（或負的 2n 整倍數）時才等價於整數除以 2n！對一般負奇數右移會產生 Off-by-one 誤差。

Pitfall：浮點數加法不具結合律！(x+y)+z ≠ x+(y+z)
令 x = -1.5 × 1038, y = +1.5 × 1038, z = 1.0：
• (x + y) + z：
= (0.0) + 1.0 = 1.0
• x + (y + z)：
因 1.5 × 1038 + 1.0 對齊時 1.0 超出 24-bit 尾數被完全捨去（Absorption），故 y + z = 1.5 × 1038 ⇒ x + (y+z) = 0.0！

平行計算啟示：在多執行緒 / GPU 上平行做浮點數加總（Reduction）時，不同執行緒執行順序會改變括號結合順序，導致每次執行結果有微小差異！

1994 Intel Pentium FDIV Bug$500M Recall
  • 事故成因：Pentium 浮點除法器採用 SRT Radix-4 演算法，透過 PLA 查表每次產生 2 bits 商；工程師誤認其中 5 個 Table Entries 永遠不會被存取而將其設為 0（共 1066 個 Entries）。
  • 數學教授 Thomas Nicely 發現：
    計算 4195835 / 3145727 時，第 14~23 bits 出現錯誤（誤差在十進位第 5 位）。
  • 工程教訓：Intel 最終提列 5 億美元無條件全面召回晶片，自此催生微處理器設計的 Formal Verification（形式化驗證）工業標準。
Ch3 核心公式與考點速查總結（Concluding Remarks §3.10）Takeaways
1. 位元本無意義，指令決定詮釋：同一組 32 bits 在 add 是 2's complement、在 addu 是 Unsigned、在 add.s 是 IEEE 754 Single。
2. 電腦算術是有限範圍與精度的近似：整數有 Overflow，浮點數有 Overflow、Underflow 與 Rounding Error（不可假設實數結合律）。
3. SIMD 是最高性價比的硬體加速：僅需切斷 ALU 進位鏈並擴充向量暫存器（如 AVX 256-bit YMM），即可獲得近線性的資料平行加速。
