Eight Great Ideas in Computer Architecture（§1.2 Slide 9）

理念名稱核心設計精神本書對應實例
1. Design for Moore's Law電晶體每 18–24 月翻倍，須針對專案完成時的技術設計Ch1 製程演進、Ch4 複雜管線
2. Use Abstraction以高階抽象隱藏底層細節，提升軟硬體設計生產力Ch1/Ch2 ISA 與 ABI 分層

4. Performance via Parallelism透過多層級平行運算推升效能Ch3 SIMD、Ch4 ILP、Ch6 Multicore/GPU

傳統四類電腦 vs. PostPC 時代（§1.1）

  • Personal Computer (PC)：通用軟體，核心為 Cost/Performance 取捨。
  • Server：網路服務，強調高容量、高吞吐與高可靠性（Reliability）。
  • Supercomputer：高階科學工程運算，極致效能但市佔極小。
  • Embedded Computer：隱藏於汽車／家電中，受嚴格功耗與成本限制。
  • PostPC 雙核心主角（Slides 5–6）：
    • PMD (Personal Mobile Device)：電池供電智慧手機／平板，銷量超越 PC。
    • Cloud / WSC (Warehouse Scale Computers)：支撐 Amazon/Google 之 SaaS。
決定效能的四大層次（Slide 8）：Algorithm（運算次數）→ Language/Compiler/ISA（機器指令數 IC）→ Processor/Memory（執行速度 CPI & Tc）→ I/O & OS。
§1.3 – §1.4 Software/Hardware Layers & Five Classic Components

軟硬體分層轉換、計算機五大組件與 ISA / ABI 分界

wiki/concepts/computer-abstractions-and-eight-great-ideas.md

程式語言三層轉換與系統軟體（§1.3 Slides 10–11）

  • Systems Software 雙核心：Compiler（HLL → Machine Code）＋ Operating System（管理 I/O、配置記憶體與儲存、多工排程共享資源）。
  • ISA（Instruction Set Architecture）：硬體與底層軟體的分界介面，讓不同微架構實作（Implementation）可執行相同二進位執行檔。
  • ABI（Application Binary Interface）：ISA ＋ OS 系統軟體呼叫介面。

計算機五大經典組件與實體拆解（§1.4 Slides 12–20）

  • 1. Input & 2. Output：PostPC 以電容式多點觸控（Capacitive Multitouch）取代鍵鼠；LCD 螢幕像素鏡射自 Frame Buffer 頁框緩衝記憶體。
  • 3. Memory（分層儲存）：
    • CPU 內建高速 Cache (SRAM) ＋ 揮發性主記憶體 DRAM。
    • 非揮發次級儲存：Magnetic Disk、Flash Memory（iPad/PMD 主力）、光碟。
  • 4. Datapath（The Brawn）& 5. Control（The Brain）：分別負責算術資料運算與指揮各組件時序（如 Apple A5 SoC 內整合 2 顆 ARM 核心）。
  • Networks：LAN (Ethernet)、WAN (Internet)、Wireless (WiFi/Bluetooth)。

IC 成本與良率非線性公式（Slide 25）

Cost per die   = Cost per wafer / (Dies per wafer × Yield)
Dies per wafer ≈ Wafer area / Die area
Yield          = 1 / (1 + (Defects per area × Die area / 2))²
關鍵考點：因為 Dies per wafer ∝ 1 / Die area 且 Yield ∝ 1 / (Die area)²，當晶片面積變大時，單顆良品晶片成本約與 (Die area)³ 成正比暴增！
§1.6 Defining Performance & The Iron Law

Response Time vs. Throughput、相對效能與 CPU Time 鐵律

wiki/formulas/cpu-performance-iron-law-and-power-wall.md

1. Response Time vs. Throughput（Slides 26–29）

  • Response Time (Execution Time)：完成單一任務所需總時間。
  • Throughput (Bandwidth)：單位時間內完成的總任務數。
    • 換更快的 CPU：同時改善 Response Time 與 Throughput。
    • 加更多顆 CPU：主要提升 Throughput（亦減少排隊等待而間接改善回應時間）。
  • 相對效能定義：Performance_X = 1 / Execution_Time_X
    「X 比 Y 快 n 倍」⟺ () / () = n（例：A 跑 10s、B 跑 15s ⟹ 15/10 = 1.5×）。
  • Elapsed Time vs. CPU Time：Elapsed 包含 I/O 與 OS 多工干擾；處理器評估以純 CPU Time（User + System） 為唯一黃金標準。

2. The Iron Law of Processor Performance（Slides 30–37）

CPU Time = CPU Clock Cycles × Clock Cycle Time (Tc)
         = CPU Clock Cycles / Clock Rate (f)

CPU Clock Cycles = Instruction Count (IC) × Average CPI
                 = Σ (CPI_i × IC_i)

╔═════════════════════════════════════════════════════════════╗
║ CPU Time = Instruction Count × CPI × Clock Cycle Time       ║
║          = (Instruction Count × CPI) / Clock Rate           ║
╚═════════════════════════════════════════════════════════════╝
系統層次 (Slide 37)影響的鐵律因子
Algorithm影響 IC，亦可能影響 CPI（如 Cache 局部性）
Programming Language / Compiler同時影響 IC 與 CPI
Instruction Set Architecture (ISA)同時影響全部三項：IC、CPI、Tc！

§1.7 The Power Wall

CMOS 動態功耗公式（C × V² × f）與 1000× 時脈的歷史極限

wiki/formulas/cpu-performance-iron-law-and-power-wall.md

CMOS 動態功耗與歷史演進（Slide 38）

Power = Capacitive load × Voltage² × Frequency switched
      = C × V² × f
  • 歷史謎題：從 80286 (1982, 12.5MHz, 3.3W) 到 Pentium 4 Prescott (2004, 3600MHz, 103W)，時脈暴增 1000 倍，為何功耗僅上升 30 倍？
  • 答案：工作電壓從 5V 一路調降至 1V（V² 平方項帶來 25 倍省電紅利！）。
  • 為何撞上 Power Wall？當電壓接近 1V 後，再降壓會使電晶體漏電流（Leakage Power）失控；且空冷散熱極限約鎖死在 100–130W，無法再靠拉高時脈提升效能！

內嵌計算例題：降壓 15% ＋ 降頻 15% 的省電威力（Slide 39）

題目：新製程 CPU 的電容負載為舊 CPU 的 85%（C_new = 0.85 C_old），同時將電壓與時脈頻率各調降 15%（V_new = 0.85 V_old, f_new = 0.85 f_old），新功耗為舊功耗的幾倍？ 

Power_new / Power_old
  = (0.85 C_old × (0.85 V_old)² × 0.85 f_old) / (C_old × V_old² × f_old)
  = 0.85⁴
  = 0.52200625 ≈ 52%
結論：僅調降 15% 電壓與時脈，就能讓晶片總功耗直接砍半（降至 52%），這正是多核心時代「以多顆中頻低壓核心取代單顆超高頻核心」的物理依據！

單核成長三階段與多核挑戰（Slides 40–41）

  • 1978–1986 (25%/yr)：CISC 微碼時期（VAX）。
  • 1986–2003 (52%/yr)：RISC + Pipelining + Superscalar OoO 黃金時代。
  • 2003 後 (22%/yr)：受制於 Power Wall + ILP + Memory Latency，全面轉向 Multicore。
  • ILP vs. Multicore：ILP 對軟體透明；Multicore 卻要求工程師顯式撰寫平行程式，客服 Load Balancing 與通訊同步開銷！

§1.9 – §1.10 Pitfalls & Concluding Remarks

為什麼不能用 MIPS 作為效能指標？Chapter 1 核心總結

wiki/exercises/ch01-performance-amdahl-and-mips-traps.md

Pitfall: Using MIPS as a Performance Metric（Slide 48）

MIPS = Instruction Count / (Execution Time × 10⁶)
     = Clock Rate / (CPI × 10⁶)
  • 缺陷 1 — 無法跨 ISA 比較：不同指令集（如 x86 CISC vs MIPS RISC）單條指令完成的工作量完全不同。
  • 缺陷 2 — 忽略指令複雜度差異（MIPS 越高反而跑越慢！）：若某段程式塞滿大量簡單無用的低 CPI 指令，雖然算出來的 MIPS 很高，但因 IC 暴增，實際 Execution Time 反而更長！
  • 缺陷 3 — CPI 隨程式劇烈變動：同一顆 Core i7 跑 libquantum (CPI 0.44) 與跑 mcf (CPI 2.66) 的 MIPS 相差 6 倍。

Chapter 1 全章四大黃金定律總結（Slide 49）

  • 1. 分層抽象化（Hierarchical Abstraction）：在軟硬體之間以 ISA（The Hardware/Software Interface） 作為核心契約。
  • 2. 唯一可靠的效能指標：Execution Time（真實執行時間 = IC × CPI × Tc） 是唯一不會被誤導的標準。
  • 3. Make the Common Case Fast（Amdahl's Law）：局部加速的上限永遠受限於未被加速的比例 T_unaffected。
  • 4. Power Wall 驅動 Parallelism：電壓與散熱極限終結了單核時脈狂飆，開啟多核心與多層級平行化時代。
