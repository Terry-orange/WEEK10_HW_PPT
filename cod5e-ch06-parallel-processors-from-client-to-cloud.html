§6.1 – §6.2 · Why Parallel Processors & The Difficulty of Creating Parallel Processing Programs

平行處理器分類、平行化四大障礙與 Amdahl's Law 100 核心 0.1% 鐵律

wiki/concepts/parallel-programming-scaling-and-flynn-taxonomy.md
1. 多處理器分類與兩大平行模式Multicore vs. Cluster
  • Multicore Microprocessors（多核心微處理器）：在單一晶片 IC 內整合多個處理器核心（Core），通常共享晶片上的 L2/L3 Cache 與單一實體位址空間。
  • Clusters / Warehouse-Scale Computers (WSCs)：透過高速區域網路將數十至數萬台獨立伺服器（Nodes）連接起來的雲端叢集。
  • 兩大平行軟體模式：
    • Task-Level Parallelism (Process-Level)：多個獨立任務同時執行。
    • Data-Level Parallelism (Parallel Processing Program)：單一龐大問題切分資料由多核心協同解算。
2. 撰寫高效平行程式的四大核心障礙4 Parallel Obstacles
  • 1. Partitioning（問題切分）：必須把工作拆成可同時執行的子任務。
  • 2. Load Balancing（負載平衡）：每個核心分到的工作量必須幾乎相等（整體完成時間由最慢的那顆核心決定！）。
  • 3. Coordination & Synchronization Overhead（同步開銷）：鎖定（Locks）與屏障（Barriers）會強制核心等待。
  • 4. Communication Latency & Bandwidth（通訊成本）：核心間交換資料的延遲與記憶體頻寬瓶頸。
教科書必考推導：想在 100 顆處理器上達到 90 倍加速（Speedup = 90），循序比例能有多少？ Amdahl's Law Shock
Speedup = (1) / (Fserial + (1 - Fserial) / (P)) ⟹ 90 = (1) / (Fserial + (1 - Fserial) / (100))

代數求解： 90 × Fserial + 0.9 × (1 - Fserial) = 1 ⇒ 89.1 × Fserial + 0.9 = 1 ⇒ Fserial = (0.1) / (89.1) ≈ 0.00112 ≈ 0.1%！
震撼結論：要在 100 核心系統達到 90 倍加速，整支程式不可平行的循序比例（含 I/O、初始化、結尾加總與同步）絕對不能超過 0.1%！哪怕只有 1% 循序部分，100 核最高也只能達到 (1) / (0.01 + 0.99/100) = 50.25×。

Strong Scaling vs. Weak Scaling 核心觀念對比必考定義
  • Strong Scaling（強擴展性 — Amdahl 視角）：
    在固定問題總規模（Fixed Problem Size）下增加處理器數量 P。當 P 變大時，平行部分耗時縮小，導致固定不變的循序部分 100t 佔比急遽放大，加速比很快撞牆飽和！
  • Weak Scaling（弱擴展性 — Gustafson 視角）：
    隨處理器數量 P 等比例擴大問題規模（維持每顆核心的工作負載固定，甚至超線性增長如 N2）。此時可平行工作量從 100t 暴增為 10,000t ~ 40,000t，把固定循序開銷 100t 稀釋到 1% ~ 0.25%，輕鬆逼近線性加速！
  • Load Balancing 鐵律：在 100 × 100、100 核環境下，只要有其中 1 顆核心分到 2% (2 倍) 或 5% (5 倍) 的工作量，其餘 99 核都得空轉等它，整體加速比立刻從 91× 暴跌至 50× 與 20×！

Vector Architecture 四大核心機制 vs. 傳統 Multimedia SIMD (SSE/AVX)Vector Advantages
1. Multi-Lane Parallelism：透過 4-Lane 或 8-Lane 硬體通道同時每個週期吐出 4~8 個元素，無須修改指令碼（AVX 擴寬則需換新 Opcode）。
2. Vector Length Register & Strip Mining：當陣列長度 n ≠ 64 (MVL) 時，用硬體 Vector Length 暫存器自動處理首段餘數 `n mod MVL`。
3. Stride & Gather/Scatter：內建非連續步距（Strided Access，如矩陣 Column）與索引表間接存取（Gather-Scatter）結合 Multi-banked Memory。
4. Vector Mask Registers：將迴圈內的 if (X[i] != 0) 轉為條件遮罩位元（Predication），消除分支控制危障。
§6.4 · Hardware Multithreading: Coarse-Grained, Fine-Grained & SMT

硬體多執行緒（Hardware Multithreading）：Coarse-Grained、Fine-Grained 與 SMT

wiki/concepts/hardware-multithreading-smp-and-message-passing.md
為什麼需要 Hardware Multithreading？用其他執行緒填補長延遲 Cache Miss 氣泡！Per-Thread State: PC + Regs

硬體必須為每個硬體執行緒保留獨立的 Register File 與 Program Counter (PC)（以及獨立 Page Table Base），但共用同一套 ALU 運算單元與 Cache，使執行緒切換可在 1 個 Clock Cycle 內由硬體無縫完成（無須 OS Context Switch 數千週期開銷）。

多執行緒技術切換時機與同一週期發射來源對單一執行緒效能影響核心優缺點與代表架構
Coarse-Grained MT僅在發生長延遲 Stall (如 L2/DRAM Miss) 時切換；每週期僅 1 個 Thread不拖慢當前執行中的單一執行緒切換時需清空或凍結管線（Flush/Start-up Overhead），無法隱藏短 Stall
Fine-Grained MT每個 Clock Cycle 輪詢（Round-Robin）切換（跳過正在 Stall 的 Thread）會拉長單一執行緒的執行時間完全隱藏長短 Stalls，最大化總吞吐量（代表：Sun Niagara、NVIDIA GPU Warp）
Simultaneous MT (SMT)同一個 Clock Cycle 可從多個 Threads 混合發射多條指令！輕微競爭共用資源，整體利用率最高直接借用 Dynamic Multiple-Issue (OoO) 的 Register Renaming，同時消滅垂直與水平空槽（代表：Intel Hyper-Threading）
§6.5 – §6.7 · Shared Memory (SMP: UMA vs. NUMA) vs. Message-Passing Clusters

SMP (UMA vs. NUMA) vs. Message-Passing 叢集：100 核心平行加總實戰對比

wiki/concepts/hardware-multithreading-smp-and-message-passing.md
1. Shared Memory Multiprocessor (SMP): UMA vs. NUMASingle Address Space
  • SMP 核心定義：所有處理器核心共享單一實體位址空間（Single Physical Address Space），核心間透過對共用變數執行隱式 Load / Store 通訊，並搭配 Locks 與 synch() Barrier 同步。
  • UMA (Uniform Memory Access)：所有核心存取任何記憶體位址的延遲皆相同（透過集中式匯流排或切換器，核心數受限於匯流排頻寬，約 ≤ 8~ 16 核）。
  • NUMA (Nonuniform Memory Access)：主記憶體分散配置在各處理器節點旁，存取本地記憶體（Local Memory）極快、存取遠端節點記憶體較慢，可擴充至數十至數百核心。
2. Message-Passing Multiprocessors (Clusters / WSC)Private Address Spaces
  • 獨立私有位址空間：每個處理器節點擁有各自獨立的私有記憶體（Processor A 無法直接 `Load` Processor B 的記憶體位址）。
  • 顯式訊息傳遞（Explicit Message Passing）：節點間必須呼叫 send(recipient, data) 與 receive() API 透過網路傳送封包（如 MPI 標準）。
  • 優點：無須昂貴的跨晶片硬體 Cache Coherence 電路，可擴展至數萬台伺服器的雲端超大規模資料中心（Warehouse-Scale Computers）。
教科書範例：100 顆處理器平行加總 100,000 個數字（每核先算 1,000 個局部和，再做二元樹 Reduction）Tree Reduction
A. Shared Memory (SMP) 樹狀歸約：
sum[Pn] = 0;
for (i = 1000*Pn; i < 1000*(Pn+1); i++) sum[Pn] += A[i];
half = 100;
repeat {
  synch(); /* 關鍵 Barrier：等待所有核心算完本輪！ */
  if (half%2 != 0 && Pn == 0) sum[0] += sum[half-1];
  half = half / 2;
  if (Pn < half) sum[Pn] += sum[Pn + half];
} until (half == 1);
B. Message-Passing (Cluster) 樹狀歸約：
sum = 0;
for (i = 0; i < 1000; i++) sum += A[i]; /* 私有陣列片段 */
half = 100;
repeat {
  half = (half + 1) / 2; /* 無須全域 Barrier，由 send/receive 同步 */
  if (Pn >= half && Pn < old_half) send(Pn - half, sum);
  if (Pn < (old_half / 2)) sum += receive();
} until (half == 1);

1. OpenMP 多執行緒平行化 Blocked AVX DGEMM1 Pragma Line!
#include <omp.h>
void dgemm (int n, double* A, double* B, double* C) {
  #pragma omp parallel for
  for (int sj = 0; sj < n; sj += BLOCKSIZE)
    for (int si = 0; si < n; si += BLOCKSIZE)
      for (int sk = 0; sk < n; sk += BLOCKSIZE)
        do_block(n, si, sj, sk, A, B, C);
}

為什麼在最外層 sj 迴圈加上 #pragma omp parallel for 完全不會有 Data Race？
因為不同的 sj 負責寫入結果矩陣 C 的完全不相交的 Column Blocks，各執行緒只共讀 A 與 B、寫入各自獨立的 C 子矩陣，零鎖定開銷！

§6.13 – §6.15 · Fallacies & Pitfalls of Parallel Processors & Course Finale

§6.13 平行處理器三大迷思與陷阱（Fallacies & Pitfalls）與計算機結構全書總結

Fallacy 1：Amdahl's Law 不適用於平行電腦？Strong vs. Weak

1987 年 Gustafson 以 Weak Scaling 在 1024 核做出近 1000× 加速後，曾有人宣稱「Amdahl's Law 已死」。事實上，只要問題規模固定（Strong Scaling）或任一子系統未隨核心數等比例放大，Amdahl's Law 永遠像重力一樣精準生效！

Fallacy 2：峰值 GFLOPS 能代表實際效能？Peak vs. Sustained

行銷規格的 Peak GFLOPS 假設所有 ALU 每拍都滿載且永遠不等待記憶體。如 Roofline Model 所示，大多數真實應用（如 SpMV AI=0.25）都卡在斜屋頂（Memory Bandwidth Bound），連峰值算力的 5% 都摸不到！

Pitfall：只看線性加速比而選了爛演算法！Speedup Baseline Trap

若拿一個時間複雜度較差但「很容易平行化」的演算法（如 O(N2) 排序）在 16 核跑出 15.9× 線性加速，其實際執行時間仍可能輸給在單核跑的最佳 O(N log N) 循序演算法！計算平行 Speedup 的分母必須是單核心上的最佳演算法。

《Computer Organization and Design 5th Edition》Ch1 – Ch6 硬體／軟體介面總結 The Hardware/Software Interface
1. 效能鐵律與軟硬體分工（Ch1–Ch3）：
Time = IC × CPI × TCC。演算法與編譯器決定 IC，ISA (MIPS/x86) 與算術硬體（ALU / IEEE 754 / SIMD）共同塑造 CPI 與時脈。
2. 管線化與記憶體階層（Ch4–Ch5）：
5-Stage Pipeline 與 Dynamic Multiple-Issue 挖掘 ILP；SRAM Cache + DRAM + Virtual Memory / TLB 利用 Locality 弭平數百週期的記憶體鴻溝。
3. 四重平行性的終極交響（Ch3–Ch6）：
結合 SIMD (DLP) + Loop Unrolling (ILP) + Cache Blocking (Locality) + Multicore OpenMP / GPU (TLP)，讓同一支 DGEMM 獲得 217 倍真實硬體加速！
