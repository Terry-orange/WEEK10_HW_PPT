§4.1 – §4.2 Foundations

CPU 效能因子、精簡 MIPS 子集與時脈方法論

wiki/datapaths/mips-single-cycle-datapath.md

1. 處理器效能與 MIPS 教學子集

  • Instruction Count：由 ISA 與 Compiler 決定。
  • CPI 與 Clock Cycle Time：由 CPU 硬體架構 決定。
  • 本章實作 3 類核心 MIPS 指令子集：
    Memory: lw, sw ALU: add, sub, and, or, slt Control: beq, j
  • 五個共通執行步驟：Fetch (PC → IM) → Read Regs → ALU（運算／位址／比較）→ Data Memory（僅 lw/sw）→ 更新 PC（PC+4 或 Target）與 Write Back。
  • 硬體鐵則：不同來源導線絕不可直接並接，必須用 Multiplexer (Mux) 搭配 Control Unit 選擇。

2. Combinational vs. Sequential 與時脈規則

  • Combinational Elements（組合邏輯）：無狀態記憶，輸出為輸入的即時函數（AND、Mux S ? I1 : I0、Adder、ALU）。
  • Sequential / State Elements（狀態元件）：儲存資料，採 Edge-Triggered（正緣 0→1 觸發） 更新；必要時加入 Write 致能線。
  • Clocking Methodology：組合邏輯轉換皆發生在相鄰時脈正緣之間；最長組合路徑（Critical Path）決定時脈週期下限。

Single-Cycle 關鍵設計限制與效能瓶頸

  • 雙記憶體分離：單週期內每元件限用一次，故必須分離 Instruction Memory 與 Data Memory。
  • Jump 位址串接：(PC+4)[31:28] || Instr[25:0] || 00，需額外 Jump 控制線與最外層 PC Mux。
  • 寫入控制絕不可為 X：RegWrite、MemWrite、MemRead 須明確為 0 以免破壞狀態。
  • Critical Path = lw (800ps)：IM → RF → ALU → DM → RF，違背 Making the common case fast → 導入 Pipelining。
§4.5 Pipelining Overview & Formulas

Pipelining 提升 Throughput，而非縮短單指令 Latency

Single-Cycle (800ps) vs. 5-Stage Pipelined (200ps)

lw200ps100ps200ps200ps100ps800ps

關鍵公式與非平衡效應：
• 平衡理想加速比 = 管線級數 k（洗衣機 4 批：8 / 3.5 = 2.3；持續工作：2n / (0.5n + 1.5) → 4）。
• 本例因 ID/WB 僅 100ps（不平衡），管線週期受最慢階段鎖定於 Tc = 200ps：
  → 穩態加速比 = 800ps / 200ps = 4.0（小於 5）；單條 lw 延遲由 800ps 增為 1000ps；3 條 lw 總時間由 2400ps 降至 1400ps。

為何 MIPS ISA 天生適合管線化？

  • 固定 32-bit 指令長度：單週期輕鬆 Fetch 與 Decode（對比 x86 長達 1–17 bytes 變長指令）。
  • 少量且規律的指令格式：rs、rt 位置固定，可在 ID 階段同時解碼並讀取 Register File。
  • Load/Store 定址架構：固定於 EX（第 3 級）算位址、MEM（第 4 級）存取記憶體，不與 ALU 運算混雜。
  • 記憶體對齊（Alignment）：保證單次記憶體讀寫僅需 1 個週期。
總執行時間公式（無 Stall）：
T_total = (k + n - 1) × Tc_pipe
其中 k = 管線級數，n = 指令數，Tc_pipe = max(t_i) + t_latch。

經典 Bug 與修正（Slides 56–57）

  • 錯誤版本：若 Register File 的 Write register 仍直接接自 IF/ID，當 lw 走到 WB 寫回時，IF/ID 裡早已換成後面第 3 條指令，寫進錯誤暫存器！
  • 修正方案：將 5-bit 目的暫存器編號（EX 階段由 RegDst 選出 rt/rd）隨 ID/EX → EX/MEM → MEM/WB 一路傳遞，最後在 WB 與資料同步寫回。
  • 為何 WB 後無管線暫存器？結果已寫入永久架構狀態元件 Register File。

§4.5 Pipeline Hazards · Interactive Explorer #2

三大冒險總覽與 Compiler Code Scheduling（13 → 11 Cycles）

wiki/concepts/pipelining-overview.md

1. Structural Hazard

硬體資源衝突。單一記憶體會讓 lw/sw 的 MEM 與新指令 IF 互搶產生 Bubble。
解法：分離 Instruction / Data Memory（L1 I$/D$）＋ Register File 雙讀單寫。

2. Data Hazard

後指令等待前指令產出資料。
• ALU→ALU：靠 Forwarding 達成 0 stall。
• Load-Use：無法向過去前遞，必停 1 stall 或由編譯器重排指令。

3. Control Hazard

分支結果揭曉前已預取後續指令。
解法：提早於 ID 判斷＋Predict Not Taken（錯才 Flush）＋動態 2-bit Predictor & BTB。

Double Data Hazard 與完整條件式（Slides 72–74）

add $1, $2, $3   # 走到 MEM/WB → 舊的 $1
add $1, $4, $5   # 走到 EX/MEM → 最新的 $1（必須優先！）
add $6, $1, $7   # 同時觸發 EX 與 MEM Hazard！
  • EX Hazard (ForwardA = 10)：
    EX/MEM.RegWrite && (EX/MEM.Rd != 0) && (EX/MEM.Rd == ID/EX.Rs)
  • 修正後 MEM Hazard (ForwardA = 01)：
    MEM/WB.RegWrite && (MEM/WB.Rd != 0)
    && !(EX/MEM.RegWrite && EX/MEM.Rd != 0 && EX/MEM.Rd == ID/EX.Rs)
    && (MEM/WB.Rd == ID/EX.Rs)
  • 兩大考點保護：RegWrite == 1（避免 sw/beq 誤觸）且 RegisterRd != 0（絕不可前遞覆寫 $zero）。
§4.7 Data Hazards — Stalling

Load-Use Data Hazard：無法向過去前遞時的硬體停頓

wiki/datapaths/forwarding-and-hazard-detection.md

Hazard Detection Unit 偵測條件（ID 階段）

if (ID/EX.MemRead
    and ((ID/EX.RegisterRt == IF/ID.RegisterRs)
         or (ID/EX.RegisterRt == IF/ID.RegisterRt)))
    stall the pipeline

當 lw 正在 EX（ID/EX.MemRead == 1）、緊接使用 lw 目標暫存器（rt）的指令正在 ID 時，立即觸發停頓。

硬體同步執行的三大 Stall 動作（Slide 78）

  • 1. 插入 Bubble (nop)：透過 Control 後方 Mux，將寫入 ID/EX 的 EX / M / WB 控制訊號全歸 0。
  • 2. 凍結 IF/ID (IF/IDWrite = 0)：讓 ID 階段的 and 下週期重做解碼。
  • 3. 凍結 PC (PCWrite = 0)：讓 IF 階段的 or 下週期重新擷取。

§4.8 Control Hazards

縮減分支懲罰（3 → 1 Cycle）與 Branch-in-ID 資料冒險

wiki/concepts/branch-prediction-and-control-hazards.md

分支判斷位置：MEM vs. ID（Slides 83–86）

  • 若留在 MEM 階段決定：確定跳躍時已有 3 條錯誤指令在 EX/ID/IF → 必須 Flush 3 條指令（3-cycle penalty）。
  • 移至 ID 階段（新增 Target Adder ＋ XOR 相等比較器 =）：
    • Clock 3：40: beq $1, $3, 7 在 ID 判定相等、算出目標 44 + 7×4 = 72，拉高 IF.Flush 清空誤取的 44: and。
    • Clock 4：IF 立刻擷取 72: lw，ID 為 1 個 Bubble → Taken 懲罰僅 1 週期（Not Taken 為 0 週期）。
代價：因為 beq 提早到 ID 階段就要用暫存器值比較（比一般指令早 1 週期），衍生出更嚴格的 Branch Data Hazards！

為何 1-Bit Predictor 在雙層迴圈會連續誤判兩次？

  • 第 1 次誤判：內層迴圈最後一輪結束（實際 Not Taken），1-bit 預測 Taken 失敗並立刻翻轉為 Not Taken。
  • 第 2 次誤判：外層重進內層第 1 輪（實際 Taken），1-bit 記著 Not Taken 再度誤判！
  • 2-Bit 優勢：離開內層僅由 11 → 10（仍預測 Taken），下次重進立即命中回到 11，誤判率直接砍半。

Branch Target Buffer (BTB, Slide 93)

  • 痛點：即使 BHT 準確猜對 Taken，IF 階段仍不知道目標位址，須等 ID 算完仍耗 1 cycle。
  • BTB 機制：以 PC 為索引的目標位址快取 (Branch PC → Target PC)。
  • 效果：在 IF 階段同步查表，若 Hit 且預測 Taken，下個週期立刻擷取目標指令 → 0-cycle taken branch penalty。
§4.9 Exceptions & Interrupts

MIPS CP0 例外處理、管線沖刷追蹤與 Precise Exceptions

wiki/concepts/exceptions-and-interrupts.md

MIPS CP0 單一入口 vs. Vectored Interrupts

  • Exception（內部同步）：Undefined opcode、Arithmetic overflow、syscall；Interrupt（外部非同步）：來自外部 I/O 控制器。
  • MIPS CP0 機制：EPC 存入 PC + 4（Handler 須減 4 還原）；Cause 記錄原因（0=未定義指令、1=溢位）；強制跳往 0x80000180。
  • Vectored Interrupts：依原因直接跳往不同向量位址（Undefined 0xC0000000、Overflow 0xC0000020）。

Precise vs. Imprecise Exceptions（Slides 104–105）

  • Precise Exceptions（精確例外）：嚴格依程式順序處理最早指令的例外，沖刷後方所有指令，讓外部狀態宛如循序執行；在 OoO / 多發射中需仰賴 ROB 維持。
  • Imprecise Exceptions：直接停機儲存現場交由軟體收拾；簡化硬體但 Handler 極複雜，在現代多發射 OoO 中幾乎不可行。

§4.10 Static Multiple Issue (VLIW)

超越 CPI = 1：MIPS 靜態雙發射、迴圈展開與暫存器更名

wiki/concepts/instruction-level-parallelism.md · formulas/

MIPS Static Dual-Issue（IPC = 1.25）

IPC = 1/CPI（如 4GHz 4-way = 16 BIPS, Peak CPI = 0.25）。64-bit Packet = ALU/Branch + Load/Store；1-cycle Load-Use 等效損失 2 指令槽。

CycleALU / Branch SlotLoad / Store Slot
1noplw $t0, 0($s1)
2addi $s1, $s1, -4nop
3addu $t0, $t0, $s2nop
4bne $s1, $zero, Loopsw $t0, 4($s1)
效能：5 條指令 / 4 cycles = IPC 1.25（峰值 2.0）；因 addi -4 提前，sw 位移須改為 4($s1)。

4x Loop Unrolling + Register Renaming（IPC = 1.75）

改用 $t0–$t3 消除跨迭代 Anti-dependency (Name Dependence)，14 指令 / 8 cycles：

CycALU / BranchLoad / Store
1addi $s1,$s1,-16lw $t0, 0($s1)
2noplw $t1, 12($s1)
3addu $t0,$t0,$s2lw $t2, 8($s1)
4addu $t1,$t1,$s2lw $t3, 4($s1)
5addu $t2,$t2,$s2sw $t0, 16($s1)
6addu $t3,$t3,$s2sw $t1, 12($s1)
7nopsw $t2, 8($s1)
8bne $s1,$0,Loopsw $t3, 4($s1)
IPC = 14 / 8 = 1.75（每元素 4→2 cycles = 2.0× 實質加速），代價是暫存器與程式碼體積增加。

條件：完整 Forwarding ＋ Hazard Detection ＋ 前半寫後半讀 ＋ Branch 在 ID（Predict Not Taken，本例實際 Taken）

開銷 #1：Load-Use Stall

add $t1, $t0, $s1 緊接 lw $t0 → CC 4 強制停 1 週期，CC 5 由 MEM/WB → EX 前遞 $t0。

開銷 #2：Branch Data Stall

beq $t1, $s2 在 ID 緊接 add $t1 → CC 6 於 ID 停 1 週期，等 add 跑完 EX 後由 EX/MEM → ID 前遞 $t1。

CC 6 判定 Taken，拉高 IF.Flush 沖刷誤取的 sub（1 週期），CC 7 改取目標 or，共耗 11 cycles！

§4.14 Fallacies, Pitfalls & Review Checklist

Ch4 六大高頻考試易錯點與 §4.14 設計迷思

wiki/exercises/ch04-pipeline-hazards-and-scheduling-traps.md

六大高頻考試易錯點（Traps）

  • Trap 1（Throughput ≠ Latency）：5 級管線不縮短單指令時間（lw 800→1000ps），不平衡時加速比小於 5。
  • Trap 2（Double Data Hazard & $0）：MEM Forwarding 必檢 Rd != 0 且 !(EX Hazard)，確保最新值優先且不汙染 $zero。
  • Trap 3（EX vs. Branch-in-ID Stall）：緊鄰 ALU→ALU 0 stall，但 ALU→beq 1 stall；緊鄰 lw→ALU 1 stall，但 lw→beq 2 stalls！
  • Trap 4（Write Reg 傳遞）：目的暫存器編號必隨 ID/EX → EX/MEM → MEM/WB 傳至 WB。
  • Trap 5（Control Don't-Care）：寫入控制 RegWrite / MemWrite / MemRead 絕不可填 X。
  • Trap 6（EPC 偏移）：硬體寫入 EPC 的是 PC + 4，Handler 須減 4 還原。

§4.14 Fallacies & Pitfalls（Slides 135–137）

  • Fallacy 1 —「Pipelining is easy」：原理直觀，但魔鬼全在細節（Double Data Hazard、Branch Stall、OoO Precise Exceptions）。
  • Fallacy 2 —「Pipelining 與製程技術無關」：電晶體紅利才使深管線與 OoO 可行；ISA 亦須隨技術演進（如 Predicated Instructions）。
  • Pitfall —「不良 ISA 設計大幅拖累管線化」：
    1. 複雜變長 ISA（VAX / IA-32）：被迫耗費前端轉譯成 micro-ops。
    2. 複雜定址模式（暫存器更新副作用或間接記憶體定址）。
    3. Delayed Branches：短管線的 ISA 延遲槽在現代深管線成為歷史包袱。
全章總結：ISA 與 Datapath/Control 互為因果；Pipelining 與 ILP 靠並行換吞吐，卻終究受限於資料相依與 Power Wall。
