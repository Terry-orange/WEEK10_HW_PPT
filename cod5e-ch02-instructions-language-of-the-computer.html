§2.1 – §2.3 Design Principles & Register File

四大硬體設計黃金原則與 MIPS 32 × 32-Bit 暫存器配置

wiki/isa/mips-registers-memory-and-number-representations.md

四大設計黃金原則（Four Design Principles）

  • 1. Simplicity favors regularity（簡潔有助規律）：所有算術指令皆固定為 3 個運算元（add a, b, c）。
  • 2. Smaller is faster（越小越快）：Register File 僅設 32 個 32-bit 暫存器（距離短、扇出小）；不常用變數才溢存（Spilling）回主記憶體。
  • 3. Make the common case fast（讓常見情況更快）：提供立即值指令 addi 與恆零暫存器 $zero，免除常數 Load。
  • 4. Good design demands good compromises（優良設計需好折衷）：以 R/I/J 三種格式換取所有指令固定 32-bit 等長。

§2.3 Memory & Immediate Operands

Byte Addressing、Word Alignment (×4)、Big Endian 與 Immediate

wiki/isa/mips-registers-memory-and-number-representations.md

Load/Store、對齊限制與 Big vs. Little Endian（Slide 8）

  • Load-Store 架構：算術指令僅能操作暫存器，陣列與結構須以 lw rt, offset(rs) 載入、sw rt, offset(rs) 存回。
  • Byte Addressing & Alignment：每個位址代表 1 Byte；1 Word = 4 Bytes (32 bits)，故 Word 起始位址必為 4 的倍數（陣列索引 i 的 Byte Offset = 4 × i）。
  • Endianness（以 0x12345678 存入位址 0..3 為例）：
位元組序Addr +0Addr +1Addr +2Addr +3代表架構
Big Endian (MSB 在低位址)0x120x340x560x78MIPS、TCP/IP
Little Endian (LSB 在低位址)0x780x560x340x12x86、RISC-V

陣列存取與 Immediate 編譯實例（Slides 9–12）

# 例 1: A[12] = h + A[8]; (h 在 $s2, A 基址在$s3)
# Index 8 → Offset = 8 × 4 = 32; Index 12 → Offset = 12 × 4 = 48
lw   $t0, 32($s3)     # $t0 = A[8]
add  $t0,$s2, $t0    #$t0 = h + A[8]
sw   $t0, 48(s3)     # A[12] = t0

# 例 2: Immediate Operands (Design Principle 3: Common case fast)
addi $s3,$s3, 4      # s3 =s3 + 4
addi $s2,$s1, -1     # s2 =s1 - 1 (直接用負常數，故無 subi 指令!)

二補數取負號（Negation）與 Sign Extension（Slides 17–18）

# 1. Signed Negation (-x = ~x + 1：逐位元反相再加 1)
+2 = 0000 0000 ... 0010₂
~2 = 1111 1111 ... 1101₂
-2 = 1111 1111 ... 1101₂ + 1 = 1111 1111 ... 1110₂

+2: 0000 0010  =>  0000 0000 0000 0010

  • 需 Zero-Extend（左補 0）的指令：lbu、lhu、邏輯立即值 andi、ori！

§2.7 Instructions for Making Decisions

編譯 If-Else 與 While 迴圈、Basic Blocks 及 slt vs. sltu

wiki/isa/mips-control-flow-and-procedures-stack-frame.md

If-Else 與 While 迴圈編譯模式（Slides 31–32）

# 1. C If-Else: if (i == j) f = g + h; else f = g - h;
      bne  $s3,$s4, Else   # 測試相反條件 (i != j) 跳至 Else
      add  $s0,$s1, $s2    # f = g + h
      j    Exit
Else: sub  $s0,$s1, $s2    # f = g - h
Exit: ...

# 2. C While Loop: while (save[i] == k) i += 1;
Loop: sll  $t1,$s3, 2      # t1 = i * 4 (word offset)
      add  t1,$t1, $s6    #$t1 = &save[i]
      lw   $t0, 0($t1)      # $t0 = save[i]
      bne  $t0,$s5, Exit   # 若 save[i] != k 則跳出迴圈
      addi $s3,$s3, 1      # i += 1
      j    Loop
Exit: ...

Basic Blocks、為何無 blt 與 slt vs. sltu（Slides 33–36）

  • Basic Block（基本區塊）：除結尾外無分支指令、除開頭外無分支標籤的連續指令序列（編譯器最佳化與處理器加速的基本單位）。
  • 為何 MIPS 不設硬體 blt / bge 指令？（Slide 35）
    32-bit 大小比較（<, >=）比相等比較（=, !=）慢得多；若塞進單一分支指令會被迫拉長時脈週期拖慢所有指令！改由 slt + bne 兩步合成。
  • slt（有號）vs. sltu（無號）必考題（Slide 36）：
    設 s0 = 0xFFFFFFFF、s1 = 0x00000001：
    • slt $t0,$s0, $s1：-1 < +1 ⟹ t0 = 1
    • sltu $t0,$s0, $s1：4,294,967,295 > 1 ⟹ t0 = 0
§2.8 Supporting Procedures in Hardware

函式呼叫六步驟、jal / jr $ra 與 Leaf Procedure 追蹤

wiki/isa/mips-control-flow-and-procedures-stack-frame.md

函式呼叫六步驟與跳躍指令（Slides 37–39）

  • Step 1：Caller 將參數放入 $a0 –$a3。
  • Step 2：執行 jal ProcedureLabel（Jump and Link）：硬體自動將返回位址 PC + 4 存入 $ra (reg 31) 並跳至目標函式。
  • Step 3：Callee 調降 $sp（往低位址長）配置 Stack 空間保存 Callee-saved 暫存器。
  • Step 4：執行函式本體運算。
  • Step 5：將回傳結果放入 $v0 –$v1，從 Stack 還原暫存器並加回 $sp。
  • Step 6：執行 jr $ra（Jump Register）：將 $ra 複製回 PC 返回呼叫點（jr 亦可用於 switch Computed Jumps）。

Leaf Procedure 實例：leaf_example(g,h,i,j)（Slides 40–41）

leaf_example:
    addi $sp,$sp, -4      # 1. Stack 往下成長 4 bytes
    sw   $s0, 0($sp)       # 2. 保存 Callee-saved 的 $s0
    add  $t0,$a0, $a1     # 3.t0 = g + h (t 為 Caller-saved 免存)
    add  $t1,$a2, $a3     #t1 = i + j
    sub  s0,$t0, $t1     #    f (s0) = (g + h) - (i + j)
    add  v0,$s0, $zero   # 4. 回傳值放入$v0
    lw   $s0, 0($sp)       # 5. 從 Stack 還原 $s0
    addi $sp,$sp, 4       # 6. 彈出 Stack 空間
    jr   $ra               # 7. 返回 Caller
為什麼 $t0,$t1 不用存進 Stack？因為它們屬於 Caller-saved，契約允許 Callee 直接覆寫！

§2.9 Communicating with People

ASCII / Unicode 字元集、Byte/Halfword 指令與 strcpy 追蹤

wiki/isa/mips-control-flow-and-procedures-stack-frame.md

字元編碼與 Byte / Halfword 載入儲存（Slides 47–48）

  • ASCII (8-bit, 128 chars) → Latin-1 (256 chars) → Unicode (32-bit / 變長 UTF-8, UTF-16)。
  • Sign-Extend 載入（有號小整數）：
    • lb rt, offset(rs)（Load Byte, 8→32 bits）
    • lh rt, offset(rs)（Load Halfword, 16→32 bits）
  • Zero-Extend 載入（無號字元處理主力！）：
    • lbu rt, offset(rs)（Load Byte Unsigned，高 24 bits 補 0）
    • lhu rt, offset(rs)（Load Halfword Unsigned，高 16 bits 補 0）
  • 儲存指令：sb rt, offset(rs)、sh rt, offset(rs)（僅寫入最右端 8 或 16 bits）。

C 字串複製 strcpy(char x[], char y[])（Slides 49–50）

strcpy:
    addi $sp,$sp, -4       # 保存 $s0 (i)
    sw   $s0, 0($sp)
    add  $s0,$zero, $zero  # i = 0
L1: add  $t1,$s0, $a1      #$t1 = &y[i] (注意 char 為 1B，不必乘以 4!)
    lbu  $t2, 0($t1)        # $t2 = y[i]  (無號載入單一 byte)
    add  $t3,$s0, $a0      #$t3 = &x[i]
    sb   $t2, 0($t3)        # x[i] = y[i]
    beq  $t2,$zero, L2     # 若遇到 Null Terminator '\0' (0) 則結束
    addi $s0,$s0, 1        # i += 1
    j    L1
L2: lw   $s0, 0($sp)        # 還原 $s0 並返回
    addi $sp,$sp, 4
    jr   $ra

§2.11 Parallelism & Instructions: Synchronization

Data Race 與 MIPS 原子讀寫指令對：Load Linked (ll) / Store Conditional (sc)

wiki/concepts/program-translation-linking-and-synchronization.md

為何需要硬體 Atomic Read/Write？（Slides 57–58）

  • Data Race（資料競爭）：多處理器共享同一記憶體區域，若無同步鎖，結果會隨存取順序改變而失真。
  • Atomic Operation：在「讀取舊鎖值」到「寫入新鎖值」之間，絕不允許其他處理器插隊修改該位址。
  • MIPS 的 RISC 解法：ll + sc 指令對：
    • ll rt, offset(rs)（Load Linked）：讀取一個 Word 存入 rt，硬體開始監控該記憶體位址。
    • sc rt, offset(rs)（Store Conditional）：若自 ll 以來該位址未被其他核心修改，則將 rt 寫入記憶體並把 rt 設為 1（成功）；否則不寫入記憶體並把 rt 設為 0（失敗）！

經典實作：Atomic Swap（原子交換 `$s4` 與 `0($s1)`，Slide 58）

try: add $t0,$zero, $s4   #t0 = 欲寫入記憶體的交換值 (s4)
     ll  $t1, 0($s1)       # Link 載入記憶體舊值至 $t1
     sc  $t0, 0($s1)       # 條件寫入 $t0; 成功則$t0=1, 失敗則 t0=0
     beq t0,$zero, try   # 若 $t0 == 0 (有人插隊失敗)，跳回 try 重試!
     add $s4,$zero, $t1   # 成功! 將讀出的舊值$t1 放入 $s4
跨章連結（Ch5 Cache Coherence）：硬體如何知道「有沒有其他核心改過 `0($s1)`」？正是靠匯流排窺探（Snooping）收到其他核心發出的 Invalidate 訊號！
§2.12 Translating and Starting a Program

C 翻譯啟動四階段、Object Module 六區段、DLL Lazy Linkage 與 JVM/JIT

虛擬指令（`$at`）與 Object Module 六區段（Slides 60–61）

  • Pseudoinstructions：move $t0,$t1 → add $t0,$zero,$t1；blt $t0,t1,L → 借用 at (reg 1) 展開為 slt $at,$t0,$t1 + bne $at,$zero,L。

  • Dynamic Linking 優勢：避免靜態連結導致執行檔臃腫（Image bloat），且自動套用新版函式庫修復。
  • Lazy Linkage（Slide 65）：首次呼叫經 Indirection Table → Stub → Dynamic Linker 載入 DLL 並改寫跳躍表指標；第二次呼叫即直接一步跳入 DLL！

§2.13 – §2.14 C Sort Example & Arrays vs. Pointers

Bubble Sort（swap + sort）、編譯最佳化啟示與陣列 vs. 指標

wiki/comparisons/mips-vs-arm-and-x86-isa.md

C Bubble Sort 雙函式結構與效能啟示（Slides 67–74）

  • swap(int v[], int k)（Leaf）：僅用 $t0,$t1, t2 計算 &v[k] = v + 4*k 並以 0(t1)、4($t1) 交換，零 Stack 開銷。
  • sort(int v[], int n)（Non-Leaf）：因內層迴圈呼叫 jal swap，開頭配置 20 bytes 保存 $ra,$s3, $s2,$s1, $s0（將參數 $a0,$a1 備份於 $s2,$s3，迴圈索引 i,j 放 $s0,$s1）。
  • 三大實測教訓（Slide 74）：
    1. gcc -O3 雖使平均 CPI 微升，但因 Inlining 大砍 IC，總加速達 2.37×。
    2. Java JIT 遠快於 JVM 直譯，接近最佳化 C。
    3. Nothing can fix a dumb algorithm!（Quicksort 比 Bubble 快 1500× 以上）。

Arrays (`clear1`) vs. Pointers (`clear2`)（Slides 75–77）

# clear1 (Array Indexing: 迴圈內 6 條指令，每次算 i*4)
loop1: sll $t1,$t0,2  ; add $t2,$a0,$t1 ; swzero,0($t2)
       addi $t0,$t0,1 ; slt $t3,$t0,$a1 ; bnet3,$zero,loop1

# clear2 (Pointer: 迴圈外先算末位址 $t2 = &array[size]，迴圈內僅 4 條指令!)
loop2: sw   $zero, 0($t0)   # *p = 0
       addi $t0,$t0, 4     # p = p + 1 (指標直接 +4 bytes!)
       slt  $t3,$t0, $t2   # p < &array[size] ?
       bne  $t3,$zero, loop2

§2.19 三大迷思與兩大致命陷阱（Slides 89–91）

  • Fallacy 1（複雜指令＝高效能）：複雜指令實作困難，反而可能拉長時脈拖慢所有簡單指令。
  • Fallacy 2（手寫組語比較快）：現代編譯器對超純量管線排程遠勝人類手寫，且組語易錯難維護。
  • Fallacy 3（向後相容＝ISA 不變）：x86 只增不減，至 2012 已累加破 900 條指令。
  • Pitfall 1（Word 位址忘了 +4）：相鄰 32-bit Words 位址差 4 而非 1！
  • Pitfall 2（回傳 Stack 自動變數指標）：函式返回後 Stack Frame 即失效，形成致命 Dangling Pointer！
